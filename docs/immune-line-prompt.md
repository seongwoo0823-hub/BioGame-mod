# 면역 방어선 (IMMUNE LINE) — 게임 제작 설계서 · 프롬프트

> 이 문서는 그대로 개발 지시문(프롬프트)으로 쓸 수 있게 작성했습니다.
> **장르:** 레인 디펜스(줄 방어) · **테마:** 면역세포 vs 병원체 · **그래픽:** 복셀(정육면체 블록) 로우폴리 캐주얼
> **대상:** 중·고등학생 생명과학 학습 + 캐주얼 게이머 · **플랫폼:** 웹(PC · 태블릿 · 휴대폰)

---

## 0. 한 줄 요약

몸속 조직 위 5줄 격자에 **면역세포를 배치**해서, 오른쪽에서 몰려오는 **병원체 무리**가 왼쪽 끝(심장 쪽 혈관 입구)에 닿지 못하게 막는 레인 디펜스 게임.
에너지는 **ATP**, 모든 캐릭터·배경은 **정육면체 블록으로 쌓은 복셀 아트**(통통 튀는 이동, 밝은 원색, 부드러운 그림자)로 표현한다.

---

## 1. 독창성 원칙 (반드시 지킬 것)

1. "격자 줄에 유닛을 놓아 몰려오는 적을 막는다"는 **장르 구조만** 참고한다.
2. 기존 게임의 **이름 · 캐릭터 · 대사 · 로고 · UI 그림 · 효과음 · 음악 · 맵 그림**은 하나도 쓰지 않는다.
   - 식물·좀비·해·잔디깎이·삽·집·정원 같은 원작 상징물은 쓰지 않는다.
   - 대응물은 모두 생명과학 개념으로 새로 만든다. 예: 해 → ATP, 잔디깎이 → 림프 순환 펄스, 삽 → 세포 자멸 신호.
3. 복셀 그래픽은 **"블록으로 쌓은 귀여운 3D"라는 화풍만** 참고한다.
   - 특정 게임의 캐릭터, 동물 디자인, 지형 그림을 따라 그리지 않는다.
4. 모든 캐릭터는 **실제 면역학·미생물학 사실에 근거한 능력**을 가진다(도감에 사실 설명 표시).
5. 이 저장소의 다른 게임 이름과 겹치지 않게 한다. 게임 id: `immune-line`, 파일: `games/immune-line.html`.

## 2. 기술 사양

| 항목 | 내용 |
|---|---|
| 파일 | `games/immune-line.html` 단일 파일 (CSS·JS 인라인). 외부 이미지 파일 없이 **모든 그래픽을 코드로 생성** |
| 3D 엔진 | 저장소의 `../vendor/three.min.js` (three.js r128, 전역 `THREE`) |
| 사이트 공용 스크립트 | `../device.js`, `../icons.js`, `../goal.js`, `../rank.js`, `../ilog.js` (다른 게임과 같은 순서로 `<body>` 끝에) |
| 글꼴 | Google Fonts `Black Han Sans`(제목·숫자), `Noto Sans KR`(본문). 실패해도 system-ui로 정상 표시 |
| 소리 | Web Audio API로 실시간 합성 (외부 음원 없음) |
| 저장 | `localStorage` 키 `immuneLine1` (진행도·해금·설정·기록). JSON 파싱 실패 시 기본값으로 복구 |
| 목표 연동 | 스테이지 클리어 시 `BioGoal.result('immune-line', 클리어한 스테이지 수, {...})` |
| 성능 목표 | 중급 휴대폰 60fps(최소 30fps), 동시 적 60마리 · 투사체 150개 · 파티클 400개에서도 유지 |
| 해상도 | `devicePixelRatio`는 최대 2로 제한, 휴대폰은 1.5 |

### 2-1. 렌더링 원칙 (복셀)
- **복셀 모델 생성기**: 문자열/배열 도면 → `BoxGeometry` 조각을 `BufferGeometryUtils` 없이 직접 **한 지오메트리로 병합**(정점 배열 이어 붙이기)해 모델 1개 = draw call 1개.
  - 같은 종류 유닛이 여러 개면 `InstancedMesh`로 그린다(투사체·파티클·ATP 알갱이 필수).
- 재질: `MeshLambertMaterial({vertexColors:true})` 1~2개만 사용. 면마다 명암을 정점 색에 미리 구워 넣는다(윗면 100%, 옆면 85%, 앞면 70%).
- 그림자: 방향광 1개 + `PCFSoftShadowMap`, 그림자 맵 1024(휴대폰 512). 그림자 품질은 설정에서 끌 수 있음.
- 카메라: `PerspectiveCamera` FOV 30°, 위에서 약 55° 내려다보고 보드 중심을 바라봄. 화면 비율이 바뀌면 보드 전체가 보이도록 거리를 자동 계산.
- 메모리: 화면 전환·스테이지 종료 시 지오메트리·재질·텍스처를 `dispose()`. 같은 도면은 캐시해서 재사용.

### 2-2. 게임 루프
- `requestAnimationFrame` + **고정 시간 간격 시뮬레이션(1/60초)**. 누적 시간 방식, 한 프레임 최대 5스텝까지만 처리.
- 탭이 숨겨지면(`visibilitychange`) 자동 일시정지.
- 게임 속도 ×1 / ×2 버튼. 시뮬레이션 스텝 수를 늘리는 방식으로 구현해서 결과가 같게 한다.
- 모든 무작위는 시드 난수(mulberry32)를 쓴다. 테스트에서 같은 시드면 같은 웨이브가 나와야 함.

## 3. 화면 구성 · 흐름

```
타이틀 → 월드 지도(5월드 × 5스테이지) → 세포 카드 고르기 → 전투 → 결과(별 1~3개)
         ├ 도감(면역세포 · 병원체)   ├ 무한 모드(해금 후)   ├ 설정   └ 게임 목록
```

- **타이틀**
  - 복셀 혈관 터널을 배경으로 면역세포들이 통통 튀며 지나가는 연출.
  - 버튼: [시작] [무한 모드] [도감] [설정] [게임 목록].
- **월드 지도**
  - 블록 섬 5개를 길로 연결하고, 각 섬에 스테이지 5개를 배치.
  - 잠긴 스테이지는 자물쇠, 클리어한 스테이지는 별 개수를 표시.
- **카드 고르기**
  - 해금된 면역세포 중 6장을 고른다(월드 3부터 7장, 월드 5부터 8장).
  - 오른쪽에는 이번 스테이지에 나오는 병원체 미리보기를 보여 준다.
- **전투 화면**
  - 위쪽: 카드 바(비용 · 재충전 게이지 · 잠김 상태), ATP 숫자, 웨이브 진행 막대, 일시정지, 속도.
  - 가운데: 보드.
  - 왼쪽 끝: 림프 순환 펄스 장치(줄마다 1개).
- **결과**
  - 클리어 시간, 잃은 림프 펄스 수, 남은 ATP로 별 1~3개를 준다.
  - 새로 해금된 카드는 블록이 조립되는 연출로 보여 준다.

### 3-1. 메뉴 버튼 · 기기 대응 (필수)
- 모든 화면 왼쪽 위에 **메뉴 버튼(☰)**을 둔다: [게임 목록으로] [메인 화면] [설정] [도움말].
  - 전투 중에는 일시정지 버튼(⏸)이 되고, 일시정지 창에 [계속] [다시 시작] [설정] [월드 지도] [게임 목록]을 둔다.
- `<html>`에 기기 클래스를 붙인다: `dev-phone` / `dev-tablet` / `dev-pc` + `touch` / `portrait`.
  - 판별 기준: 포인터 종류 + 짧은 변 600px.
- **PC**: 마우스로 카드 클릭 → 칸 클릭. 숫자키 1~8로 카드 선택, Space 일시정지, F 속도, Esc 취소.
- **태블릿·휴대폰 가로**
  - 카드 바를 화면 왼쪽 세로 열로 옮겨 보드를 크게 쓴다.
  - 손가락 탭과 드래그 둘 다 지원: 카드를 끌어다 칸에 놓거나, 탭한 뒤 칸을 탭한다.
- **휴대폰 세로**: 보드가 작아지므로 "가로로 돌리면 더 크게 보여요" 안내를 띄우고, [세로로 계속] 버튼을 둔다.
- **크기 규칙**
  - 모든 버튼은 최소 44×44px로 만든다.
  - 글자는 휴대폰 최소 12px, 숫자는 `Black Han Sans`를 쓴다.
  - 한글은 `word-break: keep-all`로 단어 중간에서 줄이 바뀌지 않게 한다.
  - 노치·홈 바 영역은 `env(safe-area-inset-*)`로 피한다.

## 4. 보드 · 핵심 규칙

| 항목 | 값 |
|---|---|
| 격자 | **5줄 × 9칸** (월드 4: 6줄) |
| 칸 크기 | 월드 단위 1.0 × 1.0. 칸마다 높이 0.2 블록 타일, 체크무늬 두 가지 색 |
| 병원체 출발 | 오른쪽 화면 밖 x = 10.5 |
| 방어선 | 왼쪽 끝 x = -0.6을 넘으면 그 줄의 **림프 순환 펄스** 작동 |
| 림프 순환 펄스 | 줄마다 1회용. 작동하면 그 줄의 병원체를 모두 쓸어 버림. 이미 썼는데 또 뚫리면 **패배** |
| 시작 ATP | 50 (월드 4 밤 스테이지: 50, 하늘에서 ATP가 떨어지지 않음) |
| 하늘 ATP | 낮 스테이지에서 8~11초마다 ATP 25가 천천히 떨어짐(10초 뒤 사라짐) |
| 수집 | 클릭/탭, 또는 설정의 "자동 수집" (켜면 획득량 그대로, 0.6초 뒤 자동) |
| 배치 | 빈 칸에만 놓을 수 있음(예외: 보호막류는 다른 세포 위에 겹치기 가능). ATP 부족·재충전 중이면 카드 회색 + 흔들림 |
| 제거 | **세포 자멸 신호**(카드 바 오른쪽 도구): 내 세포 1개를 없앰. 환불 없음(실수 방지를 위해 1초 길게 누르기 또는 두 번 탭) |
| 웨이브 | 스테이지마다 일반 웨이브 + **대규모 웨이브(깃발 웨이브)** 1~3회. 진행 막대에 표시 |
| 승리 | 마지막 웨이브의 병원체를 모두 처치 → 보상 연출 |

### 4-1. 전투 판정 (오류 없는 구현을 위한 규칙)
- 모든 유닛은 `lane`(정수)과 `x`(실수)를 가진다. 같은 줄끼리만 충돌·사격한다(예외 능력은 명시).
- 사격형 유닛은 **자기 줄에서 자기보다 오른쪽(x > 내 x - 0.1)에 있고, 화면 안(x < 9.8)에 들어온 적**이 있을 때만 쏜다.
- 투사체는 매 스텝 이동 후, 같은 줄의 적과 x 간격이 `(적 반경 + 0.15)` 이하면 명중한다. 한 투사체는 1회만 맞는다(관통 탄은 예외로, 맞힌 적 목록을 기록).
- 근접 공격 병원체는 앞에 세포가 있으면(같은 줄, x 차이 < 0.55) 멈춰서 **초당 피해량**을 준다. 세포가 죽으면 다음 스텝에 다시 걷는다.
- 피해 계산 순서: 방어구(헬멧류) 체력 → 본체 체력. 방어구가 깨지면 모델에서 해당 블록을 떼어 내고 파티클을 낸다.
- 감속(점액·항체)은 중복되지 않고 **가장 강한 효과 1개 + 지속시간 갱신**만 적용한다. 빙결형 정지는 감속과 별도로 계산.
- 사망 처리는 **스텝 끝에 일괄** 처리한다. 반복문 안에서 배열을 지우지 말 것(뒤에서부터 순회하거나 dead 플래그 사용).
- 유닛 id는 증가하는 정수. 타깃은 객체가 아닌 id로 저장하고, 매번 존재 여부를 확인한다.

## 5. 면역세포 (방어 유닛) — 16종

> 비용은 ATP, 재충전은 초. 체력 기준값: 일반 세포 300.
> **해금:** 스테이지를 클리어할 때마다 1종씩 해금한다(월드 1-1 시작 시 3종 보유).

## 8. 그래픽 상세 (복셀 아트 가이드)

### 8-1. 공통 스타일
- 모든 형태는 **정육면체 블록 조합**으로 만든다. 곡선은 계단식 블록으로 표현하고, 텍스처는 쓰지 않는다(정점 색만).
- 비율: 캐릭터는 **큰 머리(몸 전체의 50~60%)**, 짧은 다리, 2~3블록짜리 눈(흰자 + 검은 동공 + 하이라이트 1블록).
- 팔레트: 채도 높은 파스텔. 그림자 쪽은 같은 색상에서 명도만 내린다. 검은 외곽선은 쓰지 않는다.
- 조명은 따뜻한 햇빛, 그림자는 짙은 남색 계열.
- **움직임은 통통 튀는 "깡총" 방식**
  - 이동할 때 0.35초 주기로 위로 0.15 뛰며 착지 순간 납작(가로 1.15, 세로 0.85), 뜨는 순간 길쭉(0.9, 1.1)해진다.
  - 세포가 공격할 때도 몸 전체가 앞으로 살짝 튀었다가 돌아온다(0.12초).
- **피격**: 흰색으로 0.08초 번쩍 → 작은 블록 파편 4~6개가 튀어 바닥에서 사라진다.
- **처치**: 몸이 블록 조각(8~20개)으로 와르르 무너지며 튕긴다. 1초 뒤 바닥으로 가라앉는다(InstancedMesh 파티클).
- **배치**: 블록이 아래에서 위로 0.25초 만에 쌓이며 조립된다. "뽁" 소리.

### 8-3. 유닛 복셀 도면 요약 (가로×높이×깊이, 블록 수)
- **미토콘드리아** 7×5×4: 주황 캡슐 몸 + 안쪽 크리스타 주름(진한 주황 줄무늬 3줄). ATP를 만들 때 위로 노란 결정이 솟는다.
- **호중구** 6×7×6: 하늘색 둥근 몸, 보라색 여러 갈래 핵이 비쳐 보임, 흰 장갑 낀 팔 2개. 입에서 과립 탄(분홍 큐브) 발사.
- **상피 장벽** 6×8×3: 벽돌 같은 살구색 블록 4단. 체력이 줄면 금(어두운 블록 지그재그)이 생긴다.
- **B세포** 6×7×6: 분홍 몸 + 머리 위 Y자 항체 안테나 2개. Y자 항체 탄(노랑)을 쏜다.
- **대식세포** 9×7×8: 보라 큰 젤리 몸, 위족 2개. 삼킬 때 몸이 늘어나 덮치고 소화 중엔 배가 볼록·눈 감김.
- **보체 폭발** 4×4×4: 빨강·주황 격자 구. 깜빡이다가 3×3칸 폭발 원(블록 고리 확산).
- **기억 B세포** B세포 + 안경 블록, 안테나 3개.
- **비만세포** 7×6×6: 노란 몸에 보라 과립 점박이. 히스타민 구름은 반투명 연두 블록 덩어리.
- **킬러 T세포** 6×8×6: 짙은 파랑 몸, 빨간 머리띠, 블록 주먹(크게). 펀치 시 주먹이 0.6칸 뻗음.
- **NK세포** 5×7×5: 보라 몸, 번개 무늬. 순간 이동은 보라 잔상 블록 3개.
- **호산구** 6×7×6: 주황빨강 과립 몸, 이중엽 핵. 관통 탄은 길쭉한 주황 막대.
- **혈소판 응고막** 반투명 빨강 판(투명도 0.6) + 그물 무늬(흰 실선 블록).
- **수지상세포** 7×7×7: 사방으로 뻗은 가지 블록(나뭇가지 모양), 연두색. 강화 대상에게 연두 링.
- **인터페론** 하늘에서 떨어지는 하늘색 신호 깃발 블록 → 줄 전체에 물결.
- **섬모 상피** 6×6×4: 분홍 기둥 위에 흔들리는 털 블록 줄. 밀어낼 때 털이 파도치듯 움직임.
- **발열 반응** 화면 위에 붉은 온도계 블록이 차오르고 화면 가장자리 주황 아지랑이.

### 8-4. 병원체 도면 요약
- **감기 바이러스** 6×6×6 연두 둥근 몸 + 표면 돌기(빨강 1블록 × 10). 화난 눈썹.
- **캡시드 바이러스** 위에 회색 20면체 껍질(블록으로 각지게). 깨지면 반쪽씩 떨어짐.
- **대장균** 8×4×4 갈색 막대 + 꼬리 편모(물결 블록 줄, 애니메이션).
- **박테리오파지** 육각 머리 + 기둥 몸 + 다리 6개. 점프는 포물선.
- **결핵균** 회갈색 막대 + 두꺼운 흰 왁스 외막.
- **곰팡이 포자** 초록 털뭉치 + 작은 포자 2개로 분열.
- **독소 세균** 보라 막대, 입에서 초록 독소 방울 발사.
- **말라리아 원충** 반달 모양 분홍, 잠복 시 투명도 0.25.
- **회충** 연한 살구색 마디 8개, 마디마다 위상차를 둔 사인 움직임.
- **HIV** 작은 구 + 노란 돌기, 닿은 세포에 회색 쇠사슬 블록이 감김(무력화 표시).
- **노로 무리** 작은 파랑 구 5개가 서로 겹치지 않게 대열 이동.
- **암세포** 울퉁불퉁 어두운 빨강, 분열 시 몸이 두 덩어리로 갈라지는 연출.
- **프리온** 접힌 리본 모양 회보라 블록, 맞아도 깜빡이지 않고 "무효" 글자.
- **보스**
  - 모든 보스는 일반 적보다 4~8배 크다.
  - 등장할 때 화면이 흔들리고 이름표가 뜬다.
  - 체력 막대는 화면 위에 표시한다.

### 8-5. 배경 연출
- 보드 뒤(위쪽)에 월드별 배경 블록 풍경을 둔다.
  - 혈관 벽 기둥, 흘러가는 적혈구 블록, 폐포 풍선, 융털 숲, 림프관 빛, 뉴런 덩굴.
  - 패럴랙스로 느리게 움직인다.
- 보드 왼쪽 끝: 림프 순환 펄스 장치(파란 원통 블록, 작동 시 물결이 줄을 따라 오른쪽으로 쓸고 지나감).
- 보드 아래: 블록 지면이 계단식으로 내려가 끊기는 "떠 있는 섬" 연출.

    - 폐포: 휘파람 리드
    - 장: 통통 베이스
    - 림프절: 잔잔한 벨
    - 뇌: 긴장감 있는 신스
  - 보스전은 템포를 올린다.

## 10. 학습 요소

- **도감**: 면역세포·병원체 각각 복셀 모델을 360° 돌려 보기 + 3줄 사실 설명 + 게임 능력과 실제 기능의 연결.

```js
// 정의 데이터: 수치는 반드시 이 테이블에서만 읽는다(코드에 숫자 하드코딩 금지)
const CELLS = { neutro: { name:'호중구', cost:100, cd:7.5, hp:300, kind:'shooter', rate:1.4, dmg:20, proj:'granule', model:'neutro', fact:'…' }, … };
const PATHOGENS = { cold: { name:'감기 바이러스', hp:200, armor:0, speed:0.20, dps:100, model:'cold', tags:['virus'] }, … };
const STAGES = [ { id:'1-1', world:1, lanes:5, skyAtp:true, waves:[ { t:20, spawn:[['cold',1]] }, … ], flags:[6], unlock:'barrier' }, … ];

// 실행 상태: 매 스테이지 새로 만듦
state = { atp, time, lanes, grid:[lane][col] → cellId|null, cells:Map, foes:Map, shots:[], drops:[], fx:[], pulses:[true…], wave, seed, speed, paused };
```

- 모든 유닛은 `update(dt)` 하나만 가진다. 렌더링은 `sync(mesh)`에서 분리(시뮬레이션은 Three.js에 의존하지 않음 → 테스트 가능).
- 웨이브 정의는 시간(초)과 생성 목록. 같은 시각 생성은 줄을 랜덤으로 고르되 직전 2회와 같은 줄은 피한다.
- 저장 데이터 형식: `{v:1, cleared:{'1-1':3,…}, unlocked:[…], endlessBest, opt:{music,sfx,shadow,autoCollect,speed}}`. 버전이 다르면 이동(migrate) 함수로 변환한다.

## 12. 밸런스 기준 · 검증

- 1-1은 호중구 6개 + 미토콘드리아 4개로 여유 있게 클리어되어야 한다.
- 각 월드 보스는 그 월드에서 해금된 카드만으로 별 2개 이상 가능해야 한다.
- **자동 플레이 봇**으로 모든 스테이지를 시뮬레이션해서(렌더링 끔, ×20 속도) 다음을 확인한다.
  - 정해진 기본 배치로 클리어가 가능한지(불가능한 스테이지 0개).
  - 아무것도 놓지 않으면 반드시 패배하는지(너무 쉬운 스테이지 0개).
  - 평균 클리어 시간이 3~6분 범위인지.
- 수치 조정은 정의 테이블만 고친다.

## 13. 오류 방지 체크리스트 (완료 기준)

- [ ] 콘솔 오류 0개(페이지 로드 · 모든 화면 전환 · 스테이지 25개 · 무한 모드 30웨이브).
- [ ] `NaN`/`undefined`가 화면 숫자에 나오지 않는다(ATP, 체력, 타이머).
- [ ] 같은 칸에 두 세포가 겹치지 않는다(보호막 예외). 보드 밖에는 배치되지 않는다.
- [ ] 일시정지 중에는 ATP 생성·재충전·웨이브 시간이 멈춘다. 다시 시작하면 이어진다.
- [ ] ×2 속도와 ×1 속도의 결과가 같다(같은 시드 · 같은 입력 기록으로 비교).
- [ ] 탭 전환 후 돌아와도 적이 한꺼번에 순간 이동하지 않는다(프레임당 최대 스텝 제한).
- [ ] 스테이지를 20번 연속 재시작해도 메모리가 계속 늘지 않는다(dispose 확인).
- [ ] 화면 크기·회전이 바뀌어도 보드와 UI가 잘리지 않는다(1920×1080, 1366×768, 1180×820 터치, 820×1180 터치, 844×390 휴대폰, 390×844 휴대폰).
- [ ] 터치: 두 손가락 확대·더블탭 확대가 일어나지 않는다. 드래그 배치가 스크롤을 일으키지 않는다.
- [ ] 저장 데이터가 깨져 있어도(잘못된 JSON) 게임이 시작된다.
- [ ] 모든 버튼에 텍스트 또는 `aria-label`이 있다.
- [ ] 메뉴 버튼으로 언제든 게임 목록(`../index.html`)으로 돌아갈 수 있다.
